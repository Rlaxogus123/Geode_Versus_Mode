# 테스트 폴더의 역할과 동작

`tests/`는 게임을 실행하지 않고 일부 기능의 로직을 검증하는 개발용 폴더입니다.
현재는 음악 건너뛰기 기능과 관련된 준비 버튼의 상태 판단을 검사하는 자동 테스트가
하나 있습니다. 게임 실행 전에 매번 자동으로 동작하는 코드는 아닙니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| [CMakeLists.txt](CMakeLists.txt) | 모드 본체와 별개로 `room-controls` 실행 파일을 빌드하고 CTest에 등록합니다. |
| [RoomControls.cpp](RoomControls.cpp) | 준비 버튼에 여러 상태를 입력하고 반환된 동작, 문구, 활성 여부를 검사합니다. |
| [README.md](README.md) | 테스트 실행 명령, 모드 빌드 방법, 실제 게임에서 확인할 항목을 안내합니다. |
| [OVERVIEW.md](OVERVIEW.md) | 테스트 폴더의 구조와 검증 원리를 설명하는 이 문서입니다. |

## 검증 대상

테스트는 실제 모드 코드인 [src/RoomControls.hpp](../src/RoomControls.hpp)의
`versus::readyControl()`을 직접 호출합니다. 이 함수는 Classic 1v1과 Group 방에서
사용하는 준비 버튼의 문구와 동작을 결정합니다.

입력은 경기 시작 여부, 서버 응답 대기 여부, 방장 여부, 맵 유무, 캐시 준비 여부,
다운로드 여부, 준비 상태, 오디오 건너뛰기 여부입니다. 반환값 `ReadyControl`의
`caption`, `action`, `enabled()`를 예상 결과와 비교합니다.
버튼을 실제로 그리거나 클릭하고 준비 요청을 서버에 보내는 코드는 실행하지 않습니다.

현재 검사하는 주요 경우는 다음과 같습니다.

- 방장과 참가자 모두 다운로드 중에 음악 건너뛰기를 선택할 수 있는지 확인합니다.
- 건너뛰기 후 캐시가 준비되지 않은 상태에서는 버튼이 비활성이고, 준비되면 `Ready`가 되는지 확인합니다.
- 이미 준비한 경우 `Unready`가 되며, 캐시 준비와 다운로드 상태가 동시에 주어져도 준비가 우선되는지 확인합니다.
- 경기 시작, 서버 응답 대기, 맵 미선택 상태에서는 건너뛰기가 활성화되지 않는지 확인합니다.

## 실행 방식

1. `cmake -S tests -B build-tests`로 별도 테스트 프로젝트를 구성합니다.
   CMake 3.21 이상과 C++17을 지원하는 컴파일러가 필요하며 Geode SDK는 필요하지 않습니다.
2. 빌드하면 `RoomControls.cpp`와 위 헤더로 `room-controls` 실행 파일을 만듭니다.
3. CTest가 실행 파일을 실행하면 `assert`로 예상 결과를 검사합니다.
   하나라도 맞지 않으면 실행이 실패하고 CTest가 실패를 보고합니다.
   테스트 소스에서 `NDEBUG`를 해제하므로 Release 빌드에서도 검사가 생략되지 않습니다.

전체 명령은 [README.md](README.md)의 자동 테스트 항목에 있습니다.
현재 루트 CMake와 GitHub Actions에는 이 테스트 실행이 연결되어 있지 않으므로 별도로 실행해야 합니다.
테스트 실행 파일은 모드 본체에 포함되지 않으며, 게임 파일이나 서버 데이터를 변경하지 않습니다.

## 검증 범위의 한계

통과 결과는 입력한 상태에 대해 준비 버튼의 판단이 예상과 같다는 뜻입니다.
상태 값은 테스트에서 직접 지정하므로 실제 다운로드 완료나 네트워크 경합을 재현하지 않습니다.
`MapCache`의 전송 취소, 준비 요청과 멀티플레이 동기화, Ranked 화면의 처리,
한국어 글꼴과 버튼 배치, 경기 시작 후 오디오 동작은 이 테스트의 대상이 아닙니다.
이 항목들은 [README.md](README.md)의 게임 내 확인 목록에 따라 별도로 검증해야 합니다.
